## 一、三条决定带来的变化

三条决定把 v1 里的三个待定项都关掉了。库结构只保留最新形态，视频封面有了明确的取图顺序，工具栏直接取并集。

合并后的库归属只剩两个值：`audio` 与 `media`。

一个连带后果先说明：`media.path` 带唯一约束（tables.dart:30）。同一个文件只能落一行，所以两个栏目共用同一行数据。删除一处，另一处同步消失。这样不重复导入，也不重复占盘。

## 二、非兼容式更新后的库结构

### 归属值

- `works.library` 与 `folders.library` 的 CHECK 改成 `IN ('audio', 'media')`（tables.dart:18、tables.dart:76）。
- `media.media_type` 的 CHECK 不动，四个值原样保留（tables.dart:31）。落行时写文件自己的类型，判定函数已经现成（media_rules.dart:82）。
- 图片与视频不再各占一棵树，两棵旧树的数据在升级时清掉。

### 两个栏目怎么共用一行

- 音频导入照旧建 `audio` 作品。
- 多媒体导入建 `media` 作品。
- 多媒体栏列出两个库的作品（works_grid.dart:28 现在只比单值）。
- 进目录后同时装两类行（media_dao.dart:343-359）：音频走 `TrackDao.queryDirectInDir`，图片与视频走 `MediaDao.queryDirectInDir(path, type: null)`，后者再剔掉音频行。
- 音频栏只看 `audio` 作品，这一处不改。

## 三、视频封面

取图顺序按三级排。

1. 系统封面。Linux 读 `~/.cache/thumbnails/normal/<md5>.png`，文件名是文件 URI 的 md5。Windows 走 Shell 缩略图接口。Android 走 MediaMetadataRetriever。
2. 容器内嵌封面。现有 audio_metadata_reader 能读 MP4 系容器，识别依据是文件头部的 ftyp（mp4.dart:438-445）。MKV、AVI、WEBM、FLV 没有解析器，这一级会落空。
3. 首帧。Android 用 MediaMetadataRetriever。桌面端在系统里有 ffmpeg 时起一个进程，照 video_launcher.dart:27 的写法；没有就退回图标。

### 缓存与依赖

取到的图统一写进现有缩略图目录，命名与补齐队列都不用新写（thumbnail_cache.dart:126-131、app_state.dart:1624）。

这条链不链接任何解码库，与现有外链方式一致，THIRD_PARTY_NOTICES.md 的口径不变（:4）。当前开发环境没有 ffmpeg，也没有 gst 系列工具，只有 vlc。

如果桌面端要求首帧一定成功，就得自带解码器，libmpv 或 ffmpeg 二选一。这件事会改动许可证口径，需要单独拍板。

## 四、音频缩略图

- 数据位已存在：`media.cover_path`（tables.dart:52）。轨道侧也已有写入口 `TrackDao.setCoverPath`（track_dao.dart:136）。
- 缺一个通用写入口。照 `MediaDao.setSubtitlePath`（media_dao.dart:214）加一个 `setCoverPath` 即可，底层是 `updateRow`（media_dao.dart:203）。
- 缺一个选图入口。复用现有选图对话框与封面服务（cover_pick.dart:95、cover_service.dart:36）。
- 显示用 `CoverImage`（cover_image.dart:8）。回退顺序与 `coverForTrack` 一致：音频自己的封面，作品封面，图标（app_state.dart:2746-2750）。
- 音频栏不改。

## 五、工具条取并集

两条工具条的动作本来是同一批。只有播放全部与添加文件夹是音频侧独有，所以合并后保留一套。

| 动作 | 音频侧键值 | 视觉侧键值 | 合并后 |
| --- | --- | --- | --- |
| 全选 | track-select-all | selection-select-all | 保留，选中当前可见的媒体 |
| 添加标签 | track-batch-add-tags | selection-add-tags | 统一走 media 版接口（app_state.dart:2431） |
| 移除标签 | track-batch-remove-tags | selection-remove-tags | 统一走 media 版接口（app_state.dart:2434） |
| 移除记录 | track-remove-records | selection-delete | 已统一，两处都调 `deleteMediaByIds`（app_state.dart:746） |
| 清除选择 | track-toolbar-select | selection-clear | 保留一个，文案取「退出多选」 |
| 播放全部 | track-play-all | 无 | 保留，只对本目录的音频条目生效 |
| 添加文件夹到本作品 | track-add-folder | 无 | 保留（folder_browser.dart:282） |
| 列数、视图模式、排序 | 排序菜单 | `$library-toolbar-*` | 保留视觉侧一套（home_page.dart:421-480） |
| 标签筛选、高级筛选、刷新、清理缩略图、图片详情 | 无 | `$library-toolbar-*` | 保留 |

### 选择模型

现在有两套选择状态：`_selectionMode` 加 `_selectedTrackIds`，`_visualSelectionMode` 加 `_selectedImageIds`（app_state.dart:172、app_state.dart:187）。多媒体栏只用视觉那套。音频栏保留自己那套，不动。

窄屏策略照抄现有实现：工具栏断点 560（folder_browser.dart:114），选择条断点 520 与 300（home_page.dart:805-807）。

## 六、多媒体栏里的音频

浏览方式仍是缩略图网格，音频条目画封面磁贴。列表模式下音频行沿用音频栏的行样式与菜单（folder_browser.dart:594-712）。

点名音频磁贴时，把本目录的音频行组成专辑队列：

1. `MediaDao.queryDirectInDir` 按 `MediaType.audio` 取行（media_dao.dart:343-359）。
2. `TrackDao.queryByIds` 换成 TrackItem。
3. 交给 `player.playQueue`，与音频栏同源（app_state.dart:2547-2563、app_state.dart:2702-2706）。

图片双击仍走漫画模式（image_grid.dart:57-61）。这里要改一处：传进查看器的列表必须是本目录的图片子集，否则查看器会收到音频与视频行。

视频双击仍走外链（image_grid.dart:64-72）。播放列表只推视频，所以 `_launchExternal` 里不限类型的兜底要删掉（app_state.dart:2607-2624）。

### 导入

一次多媒体导入同时落三类文件。图片与视频直接落行。音频建议走现有音频导入流程，这样时长、内嵌封面、字幕配对与音频栏一致（import_service.dart:31-192）。

现有视觉导入只取一类路径（app_state.dart:1525-1527），作品与文件夹都按库名建（app_state.dart:1530-1551、app_state.dart:1595）。这两处改成固定 `media` 库，落行的类型取 `mediaTypeForPath` 的结果（media_rules.dart:82）。

## 十、实施结果（2026-09-30 完工）

本轮按上面的四个阶段实施完毕，全量测试 576 条通过，`flutter analyze` 只剩 5 条既有 info。与报告方案的差异如下。

| 项 | 方案 | 实施 |
| --- | --- | --- |
| 音视频封面三级链 | 系统缩略图 → 内嵌封面 → 首帧 | 一致。系统缩略图只实现 Linux（`~/.cache/thumbnails/normal`），Windows 那级留空，直接落到内嵌封面与首帧 |
| 取帧依赖 | 桌面端首帧依赖系统 ffmpeg | 一致。本机没有 ffmpeg，这条路径只有替身测试，没有真机验证 |
| 中心区装填 | 按行类型装填 | 改为按页签装填：`AppState.setBrowsingLibrary()` 由页签设置。原因是多媒体栏里点进音频作品时，作品的库归属是 `audio`，只按库归属判断会让文件夹层空掉 |
| 规则标签筛选 | 未涉及 | 补了一处。`kind:` / `ext:` 这类规则标签要回查 `tags` 表翻成列条件，否则多媒体栏按不限类型查询时字幕会漏出来 |
| 音频磁贴菜单的封面改动 | 未涉及 | `setMediaCover` 写完库要回填内存行，否则磁贴还是旧封面 |
| 版本号 | 未涉及 | 不升，仍是 `1.4.0+21` |

`MediaType.subtitle` 行仍走图片式卡片兜底渲染。默认的 tag 反选会挡掉它，用户改过排除集才会出现。双击不进查看器，这条没有用例覆盖。
